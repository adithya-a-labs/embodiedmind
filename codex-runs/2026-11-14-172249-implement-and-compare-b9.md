# Implement and compare B9

- Objective — Implement verified subgoals, progress-aware navigation and a hallway cue fix. Demonstrate 48-action feasibility for the five Key Corridor and Put Next layouts, then compare B8, navigation-only B9N and B9 on matched seeds.
- Changes — f088dd2 adds task_memory.py and progress.py, updates agent and controller registries, comparison and plot support, viewer labels and the three-task YAML roster. 4d4905d adds public-observation regression tests for all three tasks. 5e90ba8 archives feasibility witnesses. f6a83a3 archives the model-driven comparison and report/b9-comparison.md. Added this run record and updated the Notion roadmap at launch and completion.
- Rationale — B9N retains B8 memory and uses visit-weighted frontier routing. B9 tracks pickup, carried key, opening state, key release, source/reference roles and placement from public evidence. The hallway rule uses the stock centerline geometry and goes back to inspect when spawned near the fork. Added Randomized Memory to verify the cue fix alongside the two primary tasks. Deterministic control guided all executed B9 actions on these tasks, so the measured effect is the full configured policy.
- Feasibility — The official BabyAI reference bot solved five of five Put Next and one of five Key Corridor within 48 actions. Separate B9 no-inference witnesses showed successful action sequences for all five Key Corridor layouts in 27–41, Put Next in 8–14 and Randomized Memory in 7–20 actions. Feasibility report labels the stock bot entries explicitly, even though its replay adapter uses the B0 registry slot. Verified 25 archived witnesses, 930 checksums and 25 replays. The initial Key Corridor exploratory probe exposed repeated failed pickups while carrying the key. Added an observed key-release prerequisite and rechecked.
- Experiment — Source f088dd2, configs/memory-b9-dev.yaml, run outputs/memory-b9-comparison-20261114-172249, WSL user service with parallel 1 and monitor enabled. Same model, five seeds 3001–3005, 48 steps and model calls, and 768 memory bytes per condition. Service exit 0, all 45 matched episodes validated without runner errors. Verified 2,120 hashes and 45 readable GIFs. Full pytest suite passed 98 tests.
- Results — B8 and B9N solved 0/5 on each primary task and B9 solved 5/5 on each. Randomized Memory B8 5/5, B9N 3/5, B9 5/5, with mean actions 16.2, 30.4, and 13.0. B9 solved seed 3001 in seven actions using start-room geometry, while B8 also solved it in this rerun in 23. These are development comparisons and do not establish unseen transfer or the standalone effect of the cue fix.
