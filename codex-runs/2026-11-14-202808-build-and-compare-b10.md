# Build and compare B10

- Objective — Address the audited B9 gaps in a separate B10 variant and compare both on matched games and seeds.
- Implementation — de57567 adds MissionMemory, mission control, the B10 registry and viewer, statistical contrast and plots, three configs and targeted regression tests. B10 binds observed mission roles, verifies interaction preconditions and observed effects, retains a frontier target, uses closed door transitions, restores B8 local movement for Dynamic Obstacles and preserves B9's successful hallway and Key Corridor routines. B9 is retained as baseline. Experiment source de57567.
- Rationale — The prior trace audit identified insufficient exploration progress, missing interaction prerequisites and an infeasible 48-action cap for several MultiRoom layouts. Use diagnostic seeds 4001–4010 with the same model and limits in both arms. Add a distinct 80-action MultiRoom condition. The experiment tests the bundle on seeds used for diagnosis, without a transfer claim.
- Verification at launch — 101 pytest tests passed and node --check passed. Targeted cases covered repeated verify at the DoorKey door, freeing a held key to clear a blocker, and crossing doors on an over-budget MultiRoom layout. Exploratory fixed-response controller checks on the stock roster identified the blocker-carrying issue and led to the repair before launch. These checks were standalone development probes, and no full raw archive was retained for them.
- Execution — WSL user service embodiedmind-b10-20261114-202808 runs stock 220, GoToShift 60 and MultiRoom 80-action 20 episodes serially with --monitor, dedicated stdout/stderr and per-episode evidence. Run folders outputs/memory-b10-{stock,shift,multiroom-80}-20261114-202808. Added a launch checkpoint to the Notion roadmap. No push.
